# Amendment 4: interface-matched closed cells, a second weak closed model, and an open-weight capability ladder (written before its calls)

Frozen locally on 8 September 2026 (Pacific time), after the third independent review round of the rebuilt manuscript and before any call described below, including the smoke checks. Everything in `protocol.md`, `protocol_v2_addendum.md` and `protocol_v3_extensions.md` (Amendments 1–3) is unchanged; the recorded studies, their frozen source snapshots and analyses are not modified. The studies below reuse the archived heldout histories through `--source-run`, so they add no independent histories.

## Weaknesses addressed

1. **Single weak model.** Every decomposition finding (code before, after, inside; forced-call effort interaction) rests on GPT-5.4 mini; the other three configurations are near ceiling. A reviewer can read the paper as "one small model fails at bookkeeping". Studies E7–E9 add a second weak closed model and six open-weight models spanning about 3.6B to 49B active parameters, so that each finding is reported as a function of model capability rather than as a property of one model.
2. **Interface asymmetry.** The main grid used a forced answer call for OpenAI and automatic choice for Anthropic, and Amendment 3 showed the forced call depresses mini by 10–19 points. Study E6 reruns the GPT-5.4 mini and GPT-5.4 cells under automatic choice so that every placement comparison in the main table can be reported under one interface, with the forced-call cells retained as the control.
3. **Generality of the forced-call × effort interaction.** The sign flip (effort hurts under a forced call, helps under automatic choice) is shown for one model. Study E8 crosses effort with tool choice for every open-weight model that exposes a requested-effort control.

- Configurations `gpt54_low_auto` and `gpt54_high_auto`: identical to `gpt54_low`/`gpt54_high` except `tool_choice` is `auto`. Existing `mini_low_auto` and `mini_high_auto` are extended to the arms and cohort not yet run.
- Runs (each a full cartesian grid, two repetitions, 48 workers, tasks via `--source-run`):
  - `auto_mini_synthetic_v2`: `mini_low_auto` × {snapshot, state_raw, state_canonical}; `auto_mini_high_synthetic_v2`: `mini_high_auto` × {snapshot}. (Raw and canonical exist from Amendment 3.)
  - `auto_gpt54_synthetic_v1`: `gpt54_low_auto` × {raw, canonical, snapshot, state_raw, state_canonical}; `auto_gpt54_high_synthetic_v1`: `gpt54_high_auto` × {raw, canonical}.
  - `auto_profiles_v1`: {`mini_low_auto`, `gpt54_low_auto`} × {raw, canonical, snapshot, state_raw, state_canonical}; `auto_high_profiles_v1`: {`mini_high_auto`, `gpt54_high_auto`} × {raw, canonical}.
  - Requests: 576 + 192 + 960 + 384 + 1,920 + 384 = 4,416.
- Prespecified comparisons, paired by history with repetitions matched by index: (a) each automatic-choice cell minus the same configuration's forced-call cell (the interface effect per placement); (b) within the automatic interface, canonical minus raw, snapshot minus canonical, hybrid minus model, exactly as in the original analysis; (c) `gpt54_high_auto` minus `gpt54_low_auto` on raw and canonical.
- Hypothesis H6: the interface effect is positive for mini and near zero for GPT-5.4; the ordering raw < canonical < snapshot and hybrid ≥ model on canonical input is unchanged under automatic choice. Either outcome is reported. If confirmed, the main table is reported under automatic choice for every provider and the forced-call grid moves to the appendix as the interface control; if not, both are reported side by side.

## Study E8: open-weight capability ladder with the effort × interface cross

- Provider: OpenRouter's OpenAI-compatible chat-completions endpoint, each model pinned to one upstream provider with fallbacks disabled and `require_parameters` set, so every call in a cell is served by one provider (the served provider name is stored in each record and checked by the audit). Requested effort uses OpenRouter's unified `reasoning.effort`; tool calling uses the same strict integer schema; forced choice names `submit_answer`; 16,384 output tokens; no retries. Models and pinned providers (list prices on 8 September 2026):
  - `oss20b`: `openai/gpt-oss-20b` (Apache-2.0, 21B total / 3.6B active), Groq (re-pinned from DeepInfra; see transport note 10).
  - `oss120b`: `openai/gpt-oss-120b` (Apache-2.0, 117B / 5.1B), Cerebras fp16 (re-pinned from DeepInfra; see transport note 10).
  - `qwen27b`: `qwen/qwen3.8-27b` (Apache-2.0, 27B dense), AkashML fp8 (re-pinned from Parasail; see transport notes).
  - `dsflash`: `deepseek/deepseek-v4-flash-0731` (MIT, 284B / 13B), Baidu fp8 (re-pinned from DeepInfra; see transport notes).
  - `glmflash`: `z-ai/glm-5.3-flash` (MIT, 320B / 18B), Fireworks (re-pinned from CoreWeave; see transport note 9).
  - `dspro`: `deepseek/deepseek-v4-pro-0813` (MIT, 1.6T / 49B), Baidu fp8.
- Configurations: four per model, `{model}_{low|high}` (forced call) and `{model}_{low|high}_auto` (automatic choice), differing only in `reasoning.effort` and `tool_choice`.
- Runs (two repetitions each):
  - `open_synthetic_low_auto_v1`: six `_low_auto` × {raw, canonical, snapshot, state_raw, state_canonical}: 5,760.
  - `open_synthetic_high_auto_v1`: six `_high_auto` × {raw, canonical}: 2,304.
  - `open_synthetic_forced_v1`: twelve `_low`/`_high` × {raw, canonical}: 4,608.
  - `open_profiles_low_auto_v1`: six `_low_auto` × {raw, canonical, snapshot}: 1,728.
  - `open_profiles_high_auto_v1`: six `_high_auto` × {raw, canonical}: 1,152.
  - `open_profiles_forced_v1`: twelve `_low`/`_high` × {raw, canonical}: 2,304.
  - Requests: 17,856.
- Endpoints as before (future-joint, all-five, stock exact, historical joint, missing, invalid, truncated, tokens, cost), per configuration and arm.
- Prespecified comparisons, paired by history: (a) placement gains under automatic low effort per model: canonical − raw, snapshot − canonical, state-hybrid − model on raw and canonical; (b) effort effect per model and interface: `high − low` on raw and canonical, separately under forced and automatic choice, and the difference of these differences (the interaction); (c) interface effect per model at each effort: `auto − forced` on raw and canonical.
- Hypothesis H8a (placement): the canonical-over-raw and hybrid-over-model gains are largest where raw accuracy is lowest and shrink toward zero as raw accuracy approaches ceiling; residual snapshot rollout error is present for the weakest models. H8b (interaction): for models whose canonical accuracy is well below ceiling, the effort effect is negative under the forced call and non-negative under automatic choice; for models near ceiling the interaction is absent. A model that shows the reverse, or no interaction while far from ceiling, falsifies the generality claim and is reported as such. Either outcome is reported; there is no gate.
- Not claimed: compute matching across models or providers; that requested effort means the same thing across model families (each provider maps the unified effort parameter onto its own control); parameter counts as a causal variable (models differ in training, quantization and serving); realism beyond the existing cohorts.

## Smoke checks (development split, excluded from all estimates)

Three development-split checks of at most 12 calls each, one history, one repetition, before any study call: (i) the six `_low` open-weight configurations × {raw, canonical} verify that each pinned provider accepts the forced tool choice, the strict schema, the effort parameter and the output limit; (ii) the six `_high_auto` configurations × {raw, state_raw} verify the automatic path and the two-field schema; (iii) `gpt54_low_auto`, `haiku45`, `haiku45_thinking` × {raw, state_raw}. A configuration whose provider rejects a parameter is not retried; the rejection is recorded here as a transport note and the configuration is either re-pinned to another provider that advertises the parameter or dropped before dispatch. No smoke result is used to select models by accuracy.

## Shared rules

Unchanged: frozen source snapshots with SHA-256 hashes in each manifest (this document is included by the `*protocol*.md` glob); one runner under the shared lock; 48 workers with at most 24 in-flight requests per provider; no retries; an error interrupts the run and preserves every completed trace; the shared $3,000 ceiling (about $390 recorded before this amendment; the studies above are estimated at $150–250 at list prices). `extension_analysis.py` gains the new configurations and paired comparisons; it continues to reparse every response independently, verify each planned grid and task identity, and check the conservation identity on every hybrid answer. Every configuration, arm, invalid answer and regression is reported.

## Transport notes (appended before dispatch if a smoke check requires a change)

1. **Unadvertised parameters (8 September 2026, before any study call).** The first two open-weight smoke checks (`smoke_open_forced_v1`, `smoke_open_auto_v1`) failed on every call with OpenRouter HTTP 404 "No endpoints found that can handle the requested parameters": with `require_parameters` set, the pinned endpoints do not advertise `parallel_tool_calls` or the `usage` accounting flag, so no model was reached and no tokens were billed. Both fields were removed from the chat-completions payload (usage is returned by default; a response with two tool calls is a missing answer, as for every other provider). The interrupted smoke directories are preserved and excluded. This is a transport correction made before dispatch, not outcome-based selection: no model output existed.
2. **Qwen3.8-27B routing.** Parasail rejects a forced named `tool_choice` (HTTP 404 "No endpoints found that support the provided 'tool_choice' value"). A routing probe with a trivial one-field tool call and no task content found AkashML, Reka and CoreWeave accept it; `qwen27b` is re-pinned to AkashML fp8 (same list price, 99.8% uptime). Parasail, Darkbloom, Alibaba and Novita rejected the forced call.
3. Smoke checks (i) and (ii) are repeated as `smoke_open_forced_v2` and `smoke_open_auto_v2` with the corrected payload; smoke check (iii) `smoke_closed_v1` passed on the first attempt (six calls, all submitted).
4. **Second-round smoke outcome and DeepSeek V4 Flash routing.** `smoke_open_forced_v2` and `smoke_open_auto_v2` reached every pinned provider except DeepInfra's DeepSeek V4 Flash endpoint, which returned HTTP 429 on both calls (and on two further trivial routing probes with no task content). Every other call returned a parsed chat completion with the served provider recorded, reasoning-token counts that move with the requested effort, and exactly one `submit_answer` call where the model answered; observed behaviours that the study will simply count include one gpt-oss-20b refusal ("I can't provide the requested answer", a missing answer), one gpt-oss-120b high-effort response truncated at the 16,384-token limit (a missing answer), and reasoning text returned alongside the tool call for GLM and Qwen (ignored; only the tool call carries the answer). `dsflash` is re-pinned to Baidu fp8, which served both DeepSeek models on every attempt. No model output influenced any of these choices except that a provider that cannot be reached cannot be studied.
5. **Bounded transport retries for OpenRouter upstreams (before dispatch).** The original no-retry rule exists so that model outputs are never re-sampled. Third-party upstreams rate-limit (HTTP 429) and fail transiently (HTTP 5xx) far more often than the two first-party APIs, and a single such error would abort a 5,760-call grid. For the `openrouter` provider only, a call that fails with HTTP 429, HTTP 5xx or a transport exception, before any completion exists, is retried after 5, 10, 20, 40 and 80 seconds, at most six attempts in total; the attempt count is stored in the episode record (`transport_attempts`, absent when the first attempt succeeded) and reported. A call that exhausts its attempts is an error and interrupts the run exactly as before. Provider HTTP 4xx other than 429 (for example a rejected parameter) is never retried. Each pinned upstream also gets its own in-flight limit of 8 requests in addition to the 24-per-provider limit. Because the ledger reserves worst-case cost per attempt and keeps the reservation of a failed attempt, retried calls over-count spend; the ledger remains an upper bound.
6. A final two-call development check, `smoke_dsflash_v1` (`dsflash_low` × {raw, canonical}), verifies the Baidu route before dispatch.
7. **Effort mapping observed in the smoke checks.** `smoke_dsflash_v1` reached Baidu on both calls. At requested effort `low`, DeepSeek V4 Flash returned zero reasoning tokens (the upstream maps `low` onto its non-thinking mode) and answered in about 50 output tokens, whereas DeepSeek V4 Pro at `low` on the same upstream used 2,700–4,200 reasoning tokens, and gpt-oss, GLM and Qwen used hundreds to thousands. Requested effort is therefore a family-specific control, as the "Not claimed" list already states; the analysis reports observed reasoning tokens next to every effort comparison, and for DeepSeek V4 Flash the low-versus-high contrast is a no-thinking-versus-thinking contrast. No configuration was changed on this account. Dispatch of the fourteen study runs follows this note.

8. **In-flight limits for the open-weight stages (during `open_synthetic_low_auto_v1`, before the later stages started).** With 24 in-flight requests for the OpenRouter provider and 8 per pinned upstream, the first open-weight stage ran at about 16 completed calls per minute because the open models emit thousands of reasoning tokens per call (median elapsed times of one to several minutes), which would have put the six open-weight stages at roughly 18 hours. The limits are raised to 48 for the provider and 16 per upstream for the stages not yet started; the stage in progress continues under the old limits and is not interrupted. This changes request pacing only; payloads, prompts, tasks and the retry policy are unchanged, and the pacing is recorded in each run's frozen `run.py` snapshot.

9. **Interrupted first open-weight stage and GLM re-pin (before the rerun).** `open_synthetic_low_auto_v1` stopped after 154 of 5,760 calls when a `glmflash_low_auto` canonical request exhausted six transport attempts with HTTP 429 from CoreWeave (two other GLM calls had needed five attempts; every other upstream answered on the first attempt except one gpt-oss-120b call on the fourth). Per the rules the runner preserved every completed record and stopped; the directory is retained and excluded from all estimates, and no accuracy was inspected before the rerun was dispatched (only statuses and attempt counts, to diagnose transport). A twelve-way concurrent routing probe with a trivial one-field tool call and no task content found CoreWeave and Friendli rate-limiting every call, BaseTen rejecting the parameters, Together partially failing, NextBit 11/12, and Fireworks 12/12 in about one second; `glmflash` is re-pinned to Fireworks (same list price $0.15/$0.50 per 1M tokens; `structured_outputs` and `tool_choice` advertised). The transport retry schedule is extended from six to eight attempts (backoff 5, 10, 20, 40, 80, 160, 320 s), still only for HTTP 429/5xx or transport exceptions before any completion exists, with the attempt count stored per record. The stage is repeated in full as `open_synthetic_low_auto_v2` with otherwise identical payloads, followed by the remaining planned stages and E6b.

10. **Second interruption, gpt-oss re-pins, and transport-tolerant completion passes (before the rerun).** `open_synthetic_low_auto_v2` stopped after 2,335 of 5,760 calls when a `oss20b_low_auto` snapshot request exhausted eight transport attempts with HTTP 429 from DeepInfra, which hosted both gpt-oss models and had been rate-limiting them increasingly (about a quarter of gpt-oss-20b calls needed two or more attempts). The directory is preserved and excluded; only statuses and attempt counts were inspected. Sixteen-way concurrent routing probes with no task content found Cerebras (fp16) and Groq serving gpt-oss-120b and gpt-oss-20b on every call, DeepInfra rate-limiting four of six calls even at low concurrency, CoreWeave rate-limiting every call, and AkashML and Nebius rejecting the forced tool choice. `oss120b` is re-pinned to Cerebras and `oss20b` to Groq (list prices $0.35/$0.75 and $0.08/$0.30 per 1M tokens); since both interrupted runs are excluded, every analysed cell of a model comes from a single upstream. Because a single exhausted retry aborted two 5,760-call grids, the open-weight stages now run with `--transport-tolerant`: an episode whose transport attempts are exhausted (no completion ever existed) is recorded, the grid continues, and after the grid the failed episodes are moved to `transport_failures/` and re-issued with identical payloads in at most three documented completion passes (`completion_passes.json`); if any still fail, the run is interrupted as before. Non-transport provider errors (for example HTTP 400) still abort immediately, and the first-party OpenAI and Anthropic stages keep the original abort-on-error rule. This never re-samples a model output; it only re-sends requests that never reached a model. The stage is repeated in full as `open_synthetic_low_auto_v3`.

11. **Malformed tool-call arguments (before the rerun of the high-effort stage).** `open_synthetic_high_auto_v1` stopped after 704 of 2,304 calls when a DeepSeek V4 Pro high-effort raw response arrived with a `submit_answer` call whose argument string was not valid JSON; the parser raised, the episode was recorded as an infrastructure error, and the runner aborted. That is a model output, not a transport failure, so it must count as a missing answer like any other malformed output ("missing, malformed or negative outputs fail"). The runner and the independent auditor now both treat unparseable tool-call arguments as a missing answer (status `missing_answer`, answer `None`) for every provider; no earlier record is affected because none contained malformed arguments (the two first-party parsers had never encountered one). `open_synthetic_high_auto_v1` is preserved and excluded, and the stage is repeated in full as `open_synthetic_high_auto_v2`; the remaining stages follow.

12. **Completion of `open_synthetic_forced_v1` (before its completion pass).** The forced-call stage finished its grid and three completion passes with 4,593 of 4,608 episodes answered; 15 DeepSeek V4 Flash episodes (7 low, 8 high effort, all canonical or raw) still ended in HTTP 429 from Baidu after 81 exhausted-retry records in total, all preserved under `transport_failures/`. Repeating a 4,608-call grid because 15 requests never reached a model would discard nothing and gain nothing, so a `--complete-run` mode re-issues exactly the never-completed episodes of an existing interrupted tolerant run, with identical payloads, as further numbered completion passes; it refuses to run unless the remaining episodes equal the recorded transport failures, records each completion dispatch in `completion_runs.json` with the hash of the runner used, and keeps the earlier `interruption.json` under a dated name. No completed record is touched or re-sampled. `open_synthetic_forced_v1` is completed this way and then analysed like every other run; the profile stages and E6b follow.

## Amendment 4, addendum E6b: same-period GPT-5.4 forced-call replication (written before its calls)

Added 8 September 2026 after the six E6 runs completed and before any further call. Under automatic choice, GPT-5.4's synthetic snapshot and state-canonical cells came out 8 and 15 points below the forced-call cells collected on 7 September (17 vs 2 and 36 vs 6 wrong answers of 192), with unchanged reasoning-token usage, while its raw and canonical cells did not move. As with Amendment 1 for mini, a provider-side serving change between collection days cannot be distinguished from an interface effect without a contemporaneous forced-call baseline. Run `replication_gpt54_low_synthetic_v1` repeats `gpt54_low` (forced call) on the 96 synthetic heldout histories, arms snapshot and state_canonical, two repetitions (384 requests), identical frozen prompts and tasks, dispatched after the fourteen planned runs. Prespecified comparisons: (a) replication minus original forced cell (drift); (b) `gpt54_low_auto` minus replication (interface effect against the contemporaneous baseline). If (a) accounts for the gap, the drop is reported as run-to-run variation of the strong model and the interface effect for GPT-5.4 is read from (b); if (b) remains clearly negative, automatic choice is reported as harmful for GPT-5.4 on the short-input arms. Either outcome is reported; the original cells are not replaced or pooled.
